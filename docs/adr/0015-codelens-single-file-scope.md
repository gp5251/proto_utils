# CodeLens 单文件作用域：目录外文件把工作台收窄到它自己

状态：accepted（0.3.86 起）；细化 ADR-0006 的 CodeLens 入口语义，取代 0.3.83 的并集式钉住。

0.3.83 起 CodeLens「▶ 调用」把所在 proto 文件一并交给工作台，于是 `runner.protoDir` 之外的文件也能直接调用；0.3.86 把这件事做实为**替换式单文件作用域**：`ServiceRegistry.scopeToProtoFile` 只在文件位于 protoDir 之外（或没配目录 / 没开工作区）时钉住它，作用域态下 `load` 只加载这一个文件、不扫目录，服务列表因此只含它声明的接口，调用面与「复制为 grpcurl」按同一口径解析（`pinnedFile` 传进 `findProtoFileForService`；目录外文件用自身目录作 import-path、裸文件名作 proto，复制出去的命令才可直接执行）。顶栏渲染可点清除的「来源」标识，点击即 `unpin()` 回到 protoDir 全量。理由：零配置路径的价值在「打开任意 proto 点一下就能调」，列表里塞进整个目录的服务与这个意图无关；反过来，目录内的文件不收窄——扫描本就覆盖它，收窄只会砍掉「浏览全部服务」的用法。

## Considered Options

- **并集语义（protoDir ∪ 目录外文件，0.3.83 的做法）**：列表既全又多一个文件，但 `load` 要同时报 protoDir 缺失/非目录错与目录外文件的解析错，空态也回答不了「为什么没有服务」；用户点 A 文件的 ▶ 之后列表里仍有 B 文件的服务，来源与选择脱节，弃。
- **集合式作用域（多次点 CodeLens 累积多个文件）**：能覆盖「跨两个文件的服务一起看」，但作用域何时失效没有自然答案（关面板？点第 N 次？），清除入口要从「一个标识」变成「一组可删条目」，UI 与状态机都变复杂，弃——0.3.86 由集合改替换式。
- **给序列开一条「protoDir ∪ 作用域文件」的超集加载通道**：作用域态也能跑序列，但要引入第三种 `load` 模式（全量 / 单文件 / 超集），缓存键与失效规则跟着分叉，收益不抵复杂度，弃——改为作用域态直接拦住运行并说清怎么解除。

## Consequences

- 作用域态下运行序列被拒绝：序列可能引用当前筛选之外的服务，若放行，运行前整体校验（`sequence.ts`）会把那些步骤报成「方法失效」——错误信息说谎比拦住更糟。拦截时必须补发一条 `seqEvent: end/aborted`，否则 webview 侧已置的 `seqRunning` 永不复位，运行按钮死锁且清除作用域也救不回来。
- 序列运行期间来源锁定：`hasActiveSequence` 为真时 CodeLens 的切换请求只回 `scopeLocked` 提示、不动作用域，避免后续步骤换用另一份定义。
- 目录外文件不在全局 `**/*.proto` watcher 覆盖范围内，故新增 `ScopedProtoWatcher` 精确监听当前钉住文件，事件走同一个 500ms 防抖重载入口；作用域替换、清除与扩展销毁都要释放旧 watcher，否则编辑器里定义已改而工作台仍展示并调用旧 schema。
- 作用域态的空态与错误文案必须自成一分支：列表为空 = 这个文件没声明 `service`，与 protoDir 配得好不好无关，沿用旧文案会让人去改一个不相干的设置；跨目录 import 失败（ENOENT）单独给出「把 protoDir 配到 import 根后点刷新」的指引。
- 钉住是**替换**而非叠加：点另一个目录外文件的 ▶ 直接顶掉上一个作用域；文件不存在（未保存的 untitled 文档同样带 protoFile）时不动既有作用域，免得把用户无故踢回全量。
- 只清服务列表缓存，不动 `serviceFileCache` 与 `protoCache`：后两者自带 mtime:size 指纹门，盲清会让下次 `load` 全量 loadSync 整棵树，正是 0.3.48 修过的扩展宿主卡顿。
