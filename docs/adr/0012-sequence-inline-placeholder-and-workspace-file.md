# 调用序列：内联占位符管道 + 工作区文件持久化

调用序列(Sequence)要支持"后步引用前步响应"的数据管道，且要能命名复用。我们决定：引用走**内联占位符** `{{stepN.<path>}}`（`path` 复用 ResultTree 语法：`data["x"]` / `items[0]` / 根 `""`），而非可视化映射表——省掉一整套映射编辑 UI，且一处响应能注入多个字段；序列**持久化到工作区文件** `.proto-utils/sequences.json`，而非 VS Code Memento——序列与某套 proto 强绑定，进版本库才能团队共享与 review。

## Considered Options

- **映射表 UI**（源字段 → 目标请求字段的可视化行）：更可发现、可静态校验，但要新做一套映射编辑界面，UI 成本高，弃。
- **Memento / globalState 存储**：实现最省，但换机器/清缓存即丢，与"可命名复用"的初衷相悖，弃。

## Consequences

- 占位符语法与文件 schema 一旦发布即成契约（沿用本项目"字段名冻结，只增不改"惯例），后续只能增字段不能改语义。
- 占位符解析失败（路径取空）必须**显式中止序列并点名是哪个占位符、哪条路径**——静默注空会让"为什么后步返回奇怪结果"极难排查。
- 前向/自引用（`{{stepN}}` 中 N ≥ 当前步）在编辑时即可静态判定，标红提示；运行时解析失败路径作为最后兜底。
